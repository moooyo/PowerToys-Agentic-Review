# UI/UX 迭代记录

范围：当前 10 个目的地、登录、主要详情、操作准备/确认、恢复与管理流程；只修改本目录中的设计原型。使用 ui-ux-pro-max 清单、官方 Material 3 依据、独立代理审查和实际浏览器检查循环推进。

收敛准则：已接受的问题全部修正；受影响流程复测；独立代码和视觉检查不再提出新的、有证据且可执行的范围内修改。该准则不表示任何未来需求、真实用户研究或设备上都没有进一步改善空间。

## 第 1 轮：建立基线并统一设计

| ID | 问题 / 机会 | 修正 |
| --- | --- | --- |
| D01 | 原型存在多组相近圆角、颜色层次缺乏清晰角色 | 引入 M3 语义色彩、shape、type、state；集中在 material3.css |
| D02 | 输入边界复用弱分隔线；浅/深与输入背景约 1.30 / 1.63 | outline 与 outline-variant 分离；交互边界使用前者 |
| D03 | 主导航使用跨平台字形不稳定的 Unicode 符号 | 同一套 Lucide SVG、固定尺寸和可访问名称 |
| D04 | 局部重绘删除焦点元素，弹窗步骤切换焦点不稳定 | 按稳定标识恢复焦点；步骤切换、关闭和路由导航有明确焦点策略 |
| D05 | 错误只有顶部摘要；字段关联与 Enter 路径不足 | 字段旁错误 + aria-describedby；登录、改密与关键表单支持键盘提交 |
| D06 | 密码输入缺少显隐；权限控制只禁 Save | 显隐控件、本地校验保留输入；字段禁用/只读及可见原因 |
| D07 | 运营列表筛选与窄屏可达性不完整 | 补充事件/Worker/账户/仓库筛选，条件可单独清除；表格按标签重排 |
| D08 | 首次失败和后台刷新失败使用相同体验 | 后台刷新失败保留最后成功快照、时间与重试，需最新上下文的动作受限 |
| D09 | 每行有标题与重复箭头入口 | 单一整行详情按钮，减少重复 Tab 位置 |
| D10 | 报告工具、草稿及 attempt 信息不够明确 | 完整集合筛选；独立报告草稿保存/丢弃；attempt 使用不同的保留输出 |

这一轮保留已存在的准备/确认、P0、immutable report、unknown intent、Worker cleanup 边界，没有将原型或产品已有能力误称缺失。

## 第 2 轮：独立业务流程复审

| ID | 独立复审发现 | 修正 |
| --- | --- | --- |
| F01 | account 冲突对比使用 latest，但丢弃草稿仍恢复旧 saved | 同步保存快照与版本，保留/丢弃行为一致 |
| F02 | repository 接受最新配置后目录模式标签过时 | 标签从最新 intake 配置派生，支持 E2E only |
| F03 | 新账号丢弃后 password dirty 未清除 | 密码不进业务 state；丢弃同步清理脏状态 |
| F04 | 修改 grants 后部分 core 动作仍只依据 role | 统一真实模拟账户的 permission/capability/repository access；自账号变更同步当前会话 |
| F05 | 撤权后 retained payload 及换账号后的私有草稿边界不完整 | 六类业务页、搜索和 intent 读取统一检查；所有会话转换清理私有状态 |
| F06 | Locate P0 与原有 assessment/search 冲突 | 清除冲突筛选后定位第 26 条，完整集合约束保留 |
| F07 | Issue/follow-up 预览固定展示 PR SHA | 分别使用 snapshot、original PR、实际选择的 commit |
| F08 | 390px 常驻筛选把来源记录推到首屏之外 | Source Filters 面板保留全部功能与条件摘要；报告工具在窄屏渐进展开 |
| F09 | Skip 控件在取消裁切后出现在初始画面 | 默认透明且不可鼠标命中，键盘聚焦时可见 |

独立代码检查确认 unknown 不会因离开页面而变成新提交，跨分页选择和草稿仍保留。Worker 刷新不推断 cleanup，Webhook 恢复不重启既有 Task。

- 再补齐 Comments/Webhooks 的仓库读取 gate，与其余业务页一致。
- 源码流程复核已关闭第 2 轮 3 类核心问题；运营模块独立 6 条流程复核通过，未再发现新的可执行逻辑问题。

## 第 4 轮：浏览器实际路径

- 1440/900/390/320px，共 80 个页面×尺寸组合通过页面宽度和控件边界检查。
- 深色主题实测发现原型工具条继承深色文字却位于透明浅背景；为该工具条提供配对 surface。
- reviewer 登录实测发现 Import 错用 task:create：按产品源码改为 repository:manage + 仓库访问，并提供禁用原因。
- 对 Source Start 与 Task Cancel/Resume 补全具体权限、刷新或清理说明，避免只有禁用按钮。
- P0 冲突过滤、字段错误关联、刷新失败保留快照、Enter 登录、独立 Cancel 权限完成浏览器检查。

最后视觉复查补齐来源 Refresh 的粗指针 48px 宽度约束；其余 M3 状态和配对问题已关闭。独立源码审查再次确认 Import 权限映射及 Start/Cancel/Resume 说明一致，没有新增可执行问题。最后 12 组浏览器布局/标签回归通过。

所有已接受、范围内的问题已关闭，最后独立检查没有提出新项，本轮 loop 收敛。具体证据和不能外推的边界见 [VALIDATION.md](VALIDATION.md)。

## 2026-09-22 续轮：功能适配与连续工作流

用户允许功能修改以适配UI，继续沿用只改设计与原型的范围。先保存M3 / 02源码快照，再推进M3 / 03。

### 第5轮：扩大到连续任务路径

新增基于当前结果的审阅队列、跨Source/Task/Report返回上下文、视图URL恢复、正文优先报告、当前私稿保存并下一项、完整已选集合复核、准备正文反馈快照变化检测、默认最新attempt，以及取消等待的活动视图。

运营恢复同时改为区分检查回执、重发同请求和新重试，保留每次请求与结果，提供明确标注的模拟成功/失败；表单按净变化决定dirty和保存。

### 第6轮：独立流程复审

修正3类新发现：未决ActionIntent与原操作人绑定；浏览器返回单独恢复列表滚动；旧正文明确保留为manual后的来源说明与实时编辑状态一致。相关权限与服务器契约已对照产品源码。

### 第7轮：浏览器闭环与修正

- 正常报告390×844的finding标题位置从约1137px提前至763px，进入首屏。
- 浏览器Back→Discard→Forward暴露异步历史条目覆盖，改为等目标popstate再渲染，并通过同脚本回归。
- 跨页选择移除后改为相邻条目焦点；Save & Next对齐新finding标题旁的原生复制链接按钮；返回原结果恢复初始行焦点。
- 未开始调查的来源不再显示虚构Task入口或attempt；全局搜索不误建底层列表队列。
- 清理完成的Task不再显示In progress验证；保存结果取自冻结报告，旧报告不被改写。
- 最后补齐新增Report context及finding链接的粗指针48px目标。

最终88组页面/尺寸检查通过，关键新增流程已实测；独立源码复审未发现新增范围内可执行问题。续轮在该范围内收敛，具体结果见 [VALIDATION-2026-09-22.md](VALIDATION-2026-09-22.md)，后续产品落地约束见 [FUNCTIONAL-CHANGES.md](FUNCTIONAL-CHANGES.md)。

## M3 / 04 · 用户反馈后的三轮复核

1. 根据“需要 GitHub 入口、看不清结论和 next action”的反馈，新增来源链接和统一 outcome 区。改正未执行复现与待决策方案的误导文案。
2. 独立契约复审补齐真实 `pull_request` 类型和 operation capability 检查；推荐与通用准备入口统一授权规则，查看计划与准备执行仍分开。
3. 浏览器验证具体推荐、草稿保留、P0、SHA、恢复任务、未知提交与只读访问；48 组详情布局与 8 组列表检查通过，范围内最终复核无新增问题。

本版把结论与推荐操作置于 findings 前，主动调整 M3 / 03 的首条 finding 首屏目标。完整决定、样例限制与证据见 [DECISION-REVIEW.md](DECISION-REVIEW.md)。

## M3 / 05 · Finding 驱动的发表流程

1. 契约审计确认后端已支持一份 review 携带多条建议。重做原型为选择、逐条编辑、整份预览；把评审结论与 finding 发表格式分开。
2. 第二轮对照精确 wire 内容修正 summary 标题、全文 UTF-8 限制、Merge 方法值、CI 来源和未知回执、关闭来源与未就绪计划的后续动作。
3. 浏览器检查修正长清单操作栏不可达、窄屏首屏没有 finding、重绘后复选框焦点丢失、隐藏选择计数按对象比较，以及切换账号后关闭对话框内的旧正文残留。
4. 验证混合 summary/inline、多个不同位置的建议、Approve 独立草稿、P0、反馈变化、各动作参数、权限和未知结果；40 组布局检查通过。完整记录见 [PUBLICATION-REVIEW.md](PUBLICATION-REVIEW.md)。
